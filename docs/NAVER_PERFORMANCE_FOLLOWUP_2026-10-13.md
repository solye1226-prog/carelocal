# 네이버 성과 기반 후속 보완 점검

## 이번 요청에서 완료한 작업

- 네이버 서치어드바이저 웹마스터 도구에 접근했다. 현재 연결된 계정의 사이트 관리 화면에는 등록 사이트가 없으므로 케어로컬 URL별 성과를 조회하지 못했다. 신규 사이트 등록이나 계정 로그아웃·변경은 하지 않았다.
- 기존 대표 글8편과 후속 글10편, 총18편의 로컬 정적 연결을 점검했다. 대표→후속 및 후속→대표 링크가 모두 있다.
- 18편 모두 홈에서 실제 정적 앵커 링크로3단계 이내에 발견된다.
- 본문 내부 및 다른 글로 향하는 fragment 앵커의 목적 id 존재를 검사했다. 끊긴 앵커0개, 중복 id0개, 검사18/18 통과.
- 연결 오류가 발견되지 않았으므로 동일 링크를 더 추가하거나 제목을 임의로 바꾸지 않았다.
- 네이버 계정 확인 화면을 작업용 앱브라우저 탭에 유지했다. 케어로컬 성과 계정이 현재 계정과 다른지 사용자에게 확인 요청했다.

## 성과 판단의 한계

사용자가 제공한 검색 키워드 TOP30과 최근7일·30일 합계는 검색 수요의 근거다. 도착 URL·페이지별 CTR·평균 순위 자료가 아니므로 특정 글의 성과나 기여도를 확정하지 않는다. 최근7일 약500클릭·1.2만노출과 최근30일 약960클릭·2.1만노출은 제공 화면의 반올림 값이며 이번 실행에서 새로 조회한 수치가 아니다.

## URL별 자료 확보 뒤 진행할 순서

1. 같은 사이트·기기 조건의 최근7일·28일 자료를 확보한다. 플랫폼이28일을 제공하지 않으면30일을 사용하고 비교 기간을 명시한다.
2. 페이지 URL을 정규화해 대표 글과 후속 글을 각각 집계한다. 사이트 합계와 TOP30 부분 합계를 섞지 않는다.
3. 노출이 많고 CTR이 상대적으로 낮은 페이지를 고른다. 순위·검색어·표본 크기를 함께 보고 CTR 감소만으로 콘텐츠 문제를 단정하지 않는다.
4. 검색어와 실제 제목·첫 답변이 같은 질문을 다루는지 대조한다. 제목은 본문이 실제로 답하는 범위에서만 조정한다.
5. 기존 글에서 충분히 답할 수 있으면 보완한다. URL별 검색어에서 별도 질문이 확인될 때만 신규 소재 후보를 만든다.
6. 변경 전후의 기간·제목·첫 답변을 기록하고 충분한 데이터가 쌓인 뒤 비교한다. 오늘 변경을 어제 성과 증가의 원인으로 주장하지 않는다.
