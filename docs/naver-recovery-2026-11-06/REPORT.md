# 케어로컬 점검 해제 후 네이버 복구 점검

2026-11-06. 대상은 hospital.hbuby.com이며 다른 도메인과 광고 계정 설정은 변경하지 않았다.

## 확인 및 수정

- 사이트맵의 536개 URL 전부 HTTP 200, 리다이렉트 없음, 자기참조 canonical 일치, noindex 및 점검 응답 없음.
- 536개 페이지의 로컬 내부 링크 및 이미지·스크립트·스타일 경로에 누락 없음. API는 이 경로 존재 검사에서 제외.
- robots.txt는 주요 콘텐츠 수집을 허용하고 실제 사이트맵 URL을 명시한다. 사이트맵 XML은 정상 제공된다.
- HTTP 홈페이지는 HTTPS로 301 이동 후 200으로 응답한다.
- 홈페이지에 H1이 없던 부분을 기존 제목을 H1으로 변경해 수정했다. 기존 PC·모바일 폰트 크기 선택자를 H1에도 적용하고 CSS 쿼리를 갱신했다. 공개 HTML에서 반영 확인.
- 존재하지 않는 URL도 홈페이지/HTTP 200으로 응답하던 SPA 기본 폴백을 발견했다. Cloudflare 공식 문서의 404.html 방식으로 수정했다. 임의 페이지와 없는 CSS 파일이 실제 HTTP 404로 응답하는 것을 확인했다. 정상 게시글은 모두 200 유지.
- 콘텐츠 배포 커밋: 6410158, e81e52a.

## 네이버 관찰 및 재수집

- 사이트맵은 이미 2026-05-31에 등록돼 있다. 요약의 '사이트맵을 찾을 수 없습니다'는 현재 HTTP 실제 응답과 일치하지 않는다. 기존 등록을 삭제하거나 중복 제출하지 않았다. 네이버 재수집 후 진단 갱신 여부는 아직 확인되지 않았다.
- 서버 접근 실패 상세 화면은 제목·안내가 총 3개인 반면 여러 페이지 목록을 보여 모순됐다. 다운로드 CSV에는 11월 5일자 URL 3개가 포함됐다. 확인 범위를 3개로 한정하며 다른 화면 행 전체를 미색인이라고 단정하지 않는다.
- 다운로드 3개 모두 현재 HTTP 200으로 복구돼 있다. 이 3개와 수술분류표·담낭·백내장·청구 절차·홈페이지, 총 8개를 순차 수집 요청했다.
- 최신 50개 요청 이력을 저장했다. 복구 이후 기존 요청은 없었으며 11월 2일의 과거 이력과 구분했다.
- 각 새 행의 URL과 2026-11-06 등록 시각을 확인했다. 최종 접수 8개. 요청 결과는 naver-results.json, 화면은 accepted-final.png.
- 입력의 첫 상대 경로는 URL 형식 검증에서 거절돼 전송되지 않았다. 전체 URL로 수정 후 접수 확인. CT 글은 UI 갱신이 지연돼 새 행 확인 전 다음 요청을 진행하지 않았고, 재제출 없이 최종 등록을 확인했다.
- 요청 접수는 실제 수집·색인·노출 회복 완료를 의미하지 않는다. 이번 작업에서 복구 후 실제 색인 완료나 순위 회복을 확인하지 않았다.

## 검증 한계

- 전체 link checker는 docs/loan-ads-review의 외부 사이트 보관 HTML까지 검사하여 해당 사이트 상대 경로를 오류로 출력했다. 해당 보관자료는 변경하지 않았다. 대신 실제 사이트맵 536개 페이지를 별도로 검사했고 내부 경로 누락은 없었다.
- 통계는 11월 5일, 색인 집계는 11월 4일 기준이므로 오늘 복구 효과를 아직 보여주지 않는다.
- 요약 진단의 경고가 사라졌다고 보고하지 않는다. 서버 접근 문제의 현재 원인은 해소됐으나 네이버 재방문·갱신은 외부 처리 대기다.
- HTTP만 사용한 사이트 점검으로 광고 스크립트 실행·광고 클릭을 하지 않았다.
