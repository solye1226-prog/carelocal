케어로컬 점검 모드 / 복구 안내
적용 대상: hospital.hbuby.com의 Cloudflare Pages 프로젝트(carelocal).
메인 hbuby.com과 loan.hbuby.com의 설정은 변경하지 않았습니다.

2026-11-04에 사용자가 전체 사이트의 점검 화면 전환을 명시적으로 선택했습니다.
모든 콘텐츠·API·정적 파일·없는 경로는 광고 없는 HTML과 503, Retry-After:3600, Cache-Control:no-store로 응답합니다.
robots.txt와 ads.txt는 기존 내용을 그대로 유지합니다. 사이트맵과 게시글 원본을 삭제하거나 noindex/robots Disallow를 추가하지 않았습니다.
검색엔진과 일반 방문자에게 동일 응답을 제공합니다. 비밀 URL·사용자에이전트별 우회는 없습니다.

복구 방법(작업 시 별도로 사용자의 복구 요청을 확인할 것)
가장 간단한 임시 해제는 functions/_middleware.js의 MAINTENANCE_ENABLED를 false로 바꿔 배포하는 것입니다.
완전 복구는 점검 모드 전용으로 추가한 functions/_middleware.js와 _routes.json을 제거하고 배포하는 것입니다. 기존 functions/api는 유지합니다.
또는 점검 기능만 추가한 커밋 f6b6fe0을 revert하여 배포합니다. 다른 사용자 변경을 포함한 reset/강제 push는 하지 않습니다.
배포 후 홈페이지·여러 글·API의 원래 상태와 광고를 실행하지 않는 HTTP 본문 검증으로 복구를 확인합니다.

중요한 한계
503은 일시 점검의 신호이며 장기 색인 보존이나 애드센스 제한 해제를 보장하지 않습니다.
Retry-After는 재시도 권고일 뿐 1시간 뒤 자동 해제를 뜻하지 않습니다. 자동 종료 일정은 설정하지 않았습니다.
Cloudflare Pages Functions 무료 할당량 초과 시 프로젝트가 fail-open으로 설정돼 있다면 원본 정적 파일이 노출될 수 있습니다. 이 배포에서는 계정 런타임의 fail-open/closed 설정을 변경·확인하지 못했습니다.
설정의 지속 여부는 Cloudflare Pages 프로젝트의 Settings > Runtime > Fail open/closed에서 확인할 수 있습니다. DNS 변경이나 유료 플랜 업그레이드는 수행하지 않았습니다.

메인 도메인 확인
hbuby.com 홈은 Maintenance 점검 문구가 표시됐고 HTTP200, 광고 스크립트 없음으로 관찰됐습니다.
메인 도메인의 플러그인·캐시·HTTP 상태 설정은 변경하지 않았습니다.
상세 공개 응답은 hbuby-check.json과 hospital-public-results.json 참고.
